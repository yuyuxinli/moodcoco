差距分析：按优先级排列

语义缓存 / 预取 = 零
核心短板
现状：每轮重新检索，无任何缓存机制
最佳：VoiceAgentRAG 实现 316x 检索加速（110ms→0.35ms），75-86% 缓存命中率。Slow 在每轮结束后用 LLM 预测 3-5 个后续话题并预取文档
影响：检索延迟直接叠加到每轮响应时间上
参考 → VoiceAgentRAG (Salesforce Research, arXiv 2603.02206)
打断处理 = 原始级
核心短板
现状：keyword fallback 已弃用，无语义级打断
最佳：DuplexCascade 用 7 种 control token 语义区分打断/回声/沉思/继续，准确率 0.858。LTS 用 Thought Rollback 保留有效推理
影响：情绪陪伴场景下用户沉默≠结束说话，误判会打断用户倾诉
参考 → DuplexCascade (SB Intuitions, arXiv 2603.09180) + LTS-VA (arXiv 2601.19952)
发言前安全过滤 = 无
核心短板
现状：Fast 生成即发送，无 pre-speech 拦截
最佳：Stimm 的 BeforeSpeakMessage 让 Supervisor 在 TTS 前拥有否决权，可拦截危险回复
影响：情绪陪伴场景（尤其 crisis），Fast 可能说出不当内容且无法召回
参考 → Stimm (stimm-ai/stimm, StimmProtocol)
通信协议无类型化
核心短板
现状：直接写 Python 对象，无类型约束，不可分布式部署
最佳：Stimm StimmProtocol 有 5 种下行 + 4 种上行强类型 JSON 消息；LTS 用结构化 JSON schema（corrected_text + key_variables + plan）
影响：无法独立部署 Slow 到 GPU 服务器，调试困难，扩展性差
参考 → Stimm Protocol + LTS JSON State
语义触发 vs 无条件触发
中等差距
现状：Slow 每轮无条件启动，不管用户是闲聊还是深度倾诉
最佳：LTS 用 DistilBERT（5ms）判断语义完整度 >0.65 才触发 Thinker
影响：浪费算力，且闲聊轮次 Slow 的 skill 分析无意义
参考 → LTS-VoiceAgent Semantic Trigger
Thought Rollback = 无
中等差距
现状：用户打断时 Slow 完全丢弃推理结果
最佳：LTS 在用户改口时保留 Thinker 有效状态，仅回滚无效部分（打断率 5-10% vs PredGen 95-99%）
影响：打断后 Slow 从零开始，下一轮质量降级
参考 → LTS-VoiceAgent Thought Rollback
全双工 = 不支持
中等差距
现状：半双工，用户说完→AI 回→用户再说
最佳：DuplexCascade 真全双工，0.6s 微轮次，LoRA 5h 训练
影响：情绪陪伴需要"嗯""我在听"等实时回声，半双工做不到
参考 → DuplexCascade Full-Duplex
情绪识别 + 技能路由
领先优势
现状：6 种细粒度 skill 路由（crisis/calm/decision/untangle/relationship/listen），业内无人做到这个粒度
对比：DuplexCascade 仅识别"沉思"，Stimm 仅有安全过滤潜力，其余无情绪处理
记忆系统
领先优势
现状：MEMORY.md 长期记忆 + carryover[-3:] 跨轮 + SLOW_GUIDANCE.md
对比：VoiceAgentRAG 仅 TTL=300s 短期缓存，DuplexCascade 无显式记忆，Stimm 5 条滑动窗口
Same-turn Mutation
领先优势
现状：3 种 mutation tool（inject/skill/retrieval），Slow 可在 Fast 同轮次注入
对比：多数方案仅能跨轮次传递，同轮注入是 moodcoco 的差异点

建议改进路线（按业务影响排序）

P0 · 安全底线
紧急 BeforeSpeak 安全拦截
紧急 Fast↔Slow 通信协议类型化
直接影响用户安全 + 架构可扩展性
P1 · 体验跃升
高 语义级打断识别
高 语义缓存 + 话题预取
中 语义触发替代无条件启动
检索延迟 110ms→<1ms，打断误判率大幅降低
P2 · 自然度
中 Thought Rollback 机制
中 Slow 输出结构化 JSON
打断后不丢失推理，注入更精准
P3 · 前沿探索
探索 全双工 + 回声能力
探索 LoRA 微调 control tokens
需训练基础设施，中期目标

VoiceAgentRAG 语义缓存 316x Slow 用 LLM 预测后续话题 → 预取文档存入 FAISS 缓存 → Fast 命中时 <1ms Slow 每轮结束后预测 3-5 个情绪主题预取 skill context，消除检索延迟
DuplexCascade 7 种语义打断 token LLM 输出 control token 区分打断/回声/沉思/继续，准确率 0.858 情绪场景：沉默≠结束，需要区分"用户在想""用户在哭""用户想继续说"
LTS-VA Thought Rollback 用户改口时保留 Thinker 有效推理，仅回滚无效部分 Slow 的情绪分析不应因打断全部丢弃，有效部分应保留到下轮
Enterprise VA SentenceBuffer 按句子边界（非固定 token）切分 TTS 输入，避免中途截断 中文场景尤其重要："我觉得你可以…" 不应在"可以"后被截断
Stimm BeforeSpeakMessage TTS 前 Supervisor 有否决权，priority=interrupt 可实时切断 crisis 场景的安全底线：Slow 检测到危险内容时必须能拦截 Fast
Iris Speculative EOT VAD 置信度 30% 时投机生成，命中则 TTFT 提前 可与语义触发结合：低置信度时让 Fast 先输出回声，高置信度再出实质回复
