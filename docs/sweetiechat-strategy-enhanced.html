SweetieChat

Strategy-Enhanced Role-playing Framework for Diverse Scenarios Handling Emotional Support Agent
COLING 2025 中科院自动化所 Jing Ye, Lu Xiang et al. arXiv: 2412.08389 未开源

30 秒版本

LLM 做情绪支持的核心问题：策略选择偏差（偏好"安慰鼓励"，忽视"提问探索"）+ 场景单一（只会处理训练集中的问题类型）。

  • 方法：三角色 role-playing 框架 -- Seeker（求助者）+ Strategy Counselor（策略顾问，fine-tuned LLaMA）+ Supporter（支持者，GPT-4o）协同生成对话
  • 关键创新：把策略选择从 Supporter 中拆出来，交给一个专门 fine-tuned 的 Counselor 模型，避免 LLM 自带的策略偏差
  • 产出：ServeForEmo 数据集（3.7K 对话 / 62.8K 条消息），问题类型从 ESConv 的 13 类扩展到 45 类
  • 结果：在 ESConv 测试集上自动指标持平或略优于 ESConv 原始数据集训练的模型，人评中 empathy 和 overall quality 优于所有 baseline
对 moodcoco 的核心价值：策略选择独立化的思路值得借鉴（可用于 fast/slow 架构中的 slow agent 策略规划），但数据集和代码均未开源，直接可用性有限。

关键设计：Strategy Counselor 是独立 fine-tuned 的 LLaMA 模型，而不是 prompt 指令。这解决了 LLM 直接选策略时的偏差问题 -- 直接 prompt GPT-4o 选策略，会严重偏向 "Affirmation and Reassurance"（安慰）而忽视 "Question"（提问探索）。

Strategy-Enhanced 机制详解

为什么需要独立的 Strategy Counselor？

论文发现的核心问题：直接让 LLM（如 GPT-4o）在生成回复的同时选择策略，会出现严重的策略偏差：

LLM 直接选策略的偏差
  • "Affirmation & Reassurance" 被过度使用
  • "Question" 策略严重不足
  • 跳过 Exploration 阶段，直接进入 Action
  • 回复模式化、公式化
独立 Counselor 的改善
  • 策略分布更接近人类咨询师
  • 遵循三阶段帮助模型
  • 前期充分提问探索，中后期再给建议
  • 策略多样性显著提升

Strategy Counselor 训练方式

把策略选择建模为 classification task，而不是 generation task：

  • 训练数据：ESConv 数据集的人工标注策略标签（1,300 对话）
  • 输入：截至当前轮次的完整对话历史 Dij
  • 输出：最优策略标签 oi = argmax P(o | Dij)
  • 基座模型：LLaMA（论文未明确是哪个版本，推测为 LLaMA 2 或 3）
  • 关键：Counselor 只输出策略标签，不生成回复文本，职责分离

Hill 三阶段帮助模型 (Three-Stage Helping Model)

SweetieChat 的策略选择遵循心理咨询的三阶段理论框架：

数据构建流程

  1. 扩展问题类型：从 ESConv 的 13 类扩展到 45 类（5 大组），覆盖更广泛的生活场景
  2. 构建种子场景：从 ESConv + 心理学网站收集 1,000 个种子场景描述
  3. 创建 Seeker Profile：100 个手工设计的个性化角色（姓名、性别、职业、性格、爱好）
  4. GPT-4o 生成新场景/角色：通过 in-context learning 生成更多独特场景
  5. 三角色交互生成对话：Seeker-Counselor-Supporter 循环
  6. 后处理：去除不一致、过滤重复、控制长度（每条回复最多 3 句）
  7. 人工审核与精炼：最终质量把关
  8. 迭代扩展：新生成的高质量对话加入种子池，滚雪球式扩展

对 moodcoco 的价值

可直接借鉴的设计

1. 策略选择与回复生成分离

moodcoco 的 fast/slow 架构天然适配：slow agent 做策略规划（类似 Strategy Counselor），fast agent 按策略生成回复（类似 Supporter）。这比让单个模型同时选策略 + 生成回复效果更好。

2. 三阶段策略转换

Exploration → Comforting → Action 的策略分布变化可以编码进 slow agent 的策略规划逻辑中，确保前期充分探索、后期才给建议。

3. 策略分布监控

论文提供了具体的策略分布数据，可以用作 moodcoco 对话质量评估的 benchmark baseline -- 如果系统的策略分布过度偏向安慰而缺少提问，说明存在策略偏差。

4. 问题类型扩展方法

从 13 类扩展到 45 类的方法论（基于心理学文献 + GPT-4o 生成）可以用来扩展 moodcoco 的场景覆盖范围。

局限性

未开源

代码和数据集均未公开，无法直接复现或使用。只能参考方法论自行实现。

仅文本模态

数据集和评估都是纯文本，不涉及语音。moodcoco 的语音场景需要额外适配。

评估主观性大

人评 Fleiss' Kappa 仅 0.4-0.8，情绪支持质量的评估标准本身就缺乏共识。

SFT 天花板

论文自己承认单纯扩展 SFT 数据不够，需要 preference alignment。但未实施 RLHF/DPO。

策略体系保守

沿用 ESConv 的 8 种策略标签，未引入更细粒度的策略分类（如 MI 技术中的 OARS）。

GPT-4o 依赖

数据生成依赖 GPT-4o（Seeker + Supporter），数据质量上限受限于 GPT-4o 的情绪理解能力。

Bottom Line

SweetieChat 的核心洞察 -- 策略选择应该由专门模块负责，而不是让生成模型自行决定 -- 对 moodcoco 有直接参考价值。这恰好对应 Speaker+Thinker 架构中 Thinker 的策略规划职责。

但论文本身未开源任何资源，直接可用性为零。价值在于方法论验证：独立策略选择器 + 三阶段帮助模型的组合，在 8B 参数量级就能达到不错的效果。moodcoco 可以用更强的模型（minimax-m2.7）+ 更细粒度的策略体系实现更好的效果。
