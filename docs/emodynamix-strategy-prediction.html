LLM 做情感支持时有策略偏好偏差 (preference bias)：倾向于总给建议，忽略情感反映和自我暴露等策略。EmoDynamiX 的解法是将策略预测和文本生成解耦，用异构图 (heterogeneous graph) 建模用户情绪和系统策略之间的话语动态 (discourse dynamics)，先预测策略再生成回复。

核心问题：LLM 的策略偏好偏差

当 LLM 端到端生成情感支持回复时，隐式策略规划缺乏透明度，且存在严重偏差：

  • ChatGPT preference bias = 0.88，接近完全偏向少数策略
  • LLaMA3-8B preference bias = 0.83，同样严重
  • 超过 60% 的情感类策略 (Reflection of Feelings, Self-disclosure) 被错误分类为任务导向策略 (Providing Suggestions)
  • 直觉解释：LLM 被训练为"有用的助手"，导致本能倾向于给建议，而不是共情、反映感受或自我暴露
关键洞察：策略预测是一个独立的分类任务，不应该被语言生成的偏好所左右。解耦后，策略选择基于对话动态而非生成概率。

异构图建模机制

EmoDynamiX 的核心创新是用异构图 (heterogeneous graph) 建模对话中情绪和策略的动态交互。图的结构直接反映了 discourse dynamics。

三类节点

Emotion Node
用户话语的情绪状态。用混合情绪分布 pi 乘以可训练 codebook E 得到初始嵌入 ge = p · E
Strategy Node
系统话语的策略标签。用 one-hot si 乘以可训练 codebook S 得到初始嵌入 gst = s · S
Dummy Node
目标占位符，聚合所有 emotion/strategy 节点信息，输出用于最终预测

三类边

Discourse 边
由 discourse parser 解析的话语关系 (Comment, Elaboration 等)，连接相邻 emotion-strategy 节点
Self-ref 边
Strategy 节点到 Dummy 节点，让目标节点"看到"之前用过的策略
Inter-ref 边
Emotion 节点到 Dummy 节点，让目标节点"看到"用户情绪轨迹

混合情绪建模

不使用离散情绪标签，而是用概率分布表示混合情绪。通过预训练的 ERC (Emotion Recognition in Conversation) 模型输出 logits，再用可学习温度参数 τ 的 softmax 得到分布：

pi = [ exp(zji / τ) / Σk exp(zki / τ) ]j=1...|E|

7 种基础情绪：Anger, Disgust, Fear, Joy, Sadness, Surprise, Neutral。温度 τ 在训练中学习，控制分布的锐利度。

RGAT 注意力机制

使用 Relational Graph Attention Network，不同关系类型有独立的注意力权重：

αi,j(r,k) = exp(ai,j) / ΣrΣm exp(ai,m)
hi = ||k=1..K σ( Σr Σm αi,m(r,k) Wv(r,k) gm )

K 个注意力头，L 层 RGAT。不同关系类型 r 有独立参数 W，使模型区分 discourse 边、self-ref 边和 inter-ref 边的语义。

Transparency: 决策可回溯

图结构的注意力权重 α 允许回溯每次策略预测的决策依据：

Case: Dummy Node 注意力转移
用户情绪从 Sadness 转为 Fear+Sadness 后，Dummy node 的注意力从"之前用过的策略节点"转向"用户情绪转变节点"，最终选择了 Reflection of Feelings 而非继续 Question。
可解释性价值
与 LLM 黑盒不同，可以回答"为什么选这个策略"：因为注意力从 Strategy2 (Question) 移到了 Emotion3 (Fear+Sadness)，说明系统检测到情绪变化并做出了响应。

LLM 偏差模式：过度使用 Providing Suggestions (策略 6)，不足使用 Reflection of Feelings (策略 3) 和 Self-disclosure (策略 4)。EmoDynamiX 通过 weighted cross-entropy + 图结构有效缓解了这一偏差。

对 moodcoco 的价值

直接可用

  • Thinker 采用解耦架构：策略预测不交给生成模型隐式处理，Thinker 作为独立策略预测器，输出策略 label 后再指导 Speaker 生成
  • 混合情绪表示：情绪用概率分布而非离散标签，更贴合真实用户 -- "我很焦虑但也有点生气"不应被强制归为单一情绪
  • 策略偏差意识：在评估 moodcoco 时，主动检测是否过度使用 Providing Suggestions，确保 Reflection of Feelings 和 Affirmation 有足够出现频率

设计启发

  • Discourse dynamics 建模：Thinker 不只看当前轮，需要建模"之前用了什么策略 + 用户情绪怎么变化"的轨迹
  • 可解释性：策略选择需要有 trace -- 为什么选了这个策略，是因为检测到什么情绪变化
  • Weighted loss：低频策略 (Self-disclosure, Information) 需要在训练/prompt 中被显式加权，否则模型天然倾向高频策略
注意落地差异：EmoDynamiX 是训练时的监督学习框架 (RoBERTa + RGAT)，moodcoco 的 Thinker 是 inference-time 的 LLM prompt engineering。核心借鉴的是"解耦"思想和"异构图的信息结构"，不是直接复用模型。Thinker 的 system prompt 应显式包含：当前检测到的情绪分布 + 已用策略序列 + 策略选择的约束规则。

局限性

  • Ground truth 模糊性：同一对话状态下可能有多个合理策略，但数据集只标注了一个。Macro-F1 = 27.70 的"天花板"可能不只是模型问题，而是任务定义本身的局限
  • 仅评估英文数据集：ESConv 和 AnnoMI 均为英文。中文情感支持对话的策略分布可能不同（如"含蓄表达"在中文文化中更常见），泛化性未验证
  • Discourse parser 跨域问题：使用 STAC (游戏对话) 训练的 parser 应用到情感对话，消融实验显示其贡献最小 (-1.06)，说明跨域泛化不佳
  • 模型架构未充分探索：仅使用 RoBERTa + RGAT，未实验其他 backbone (如 DeBERTa) 或图网络变体 (GAT, GCN, GraphSAGE)
  • 绝对性能仍不够好：27.70 Macro-F1 意味着策略预测仍有大量错误，说明 emotional support 的策略预测是一个本质困难的任务
  • 未验证端到端效果：论文聚焦策略预测准确率，但未验证"更好的策略预测 → 更好的回复质量 → 更好的用户体验"这条因果链
