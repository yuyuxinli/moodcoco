单轮时序：一次完整交互

VAD 检测到用户说完 → Speaker 和 Thinker 并行启动。Speaker 先用已有 context 回复，Thinker 完成后注入 deps 供下轮使用。
sequenceDiagram
    autonumber
    participant U as 🎤 用户
    participant LK as ⚙️ LiveKit
(VAD+ASR+TTS)
    participant S as 🗣️ Speaker
    participant T as 🧠 Thinker
    participant M as 🌐 记忆模块
    participant D as 📋 Deps

    U->>LK: 语音输入
    LK->>LK: VAD 检测语音活动
    LK-->>LK: ASR 持续输出 partial

    Note over U,LK: 用户停止说话
VAD 检测到静音

    LK->>S: 触发 Speaker（完整 ASR 文本）
    LK->>T: 触发 Thinker（完整 ASR 文本）

    par Speaker 即时回复
        S->>D: 读取 prewarmed_contexts + 已有注入
        alt 预热命中
            D-->>S: 预组装好的 context
        else 预热未命中
            D-->>S: 默认 context
        end
        S->>S: Doubao Lite 生成回复
        S->>S: 安全层: prompt 约束 + 关键词
        S->>LK: 回复文本 → TTS
        LK-->>U: 🔊 语音输出
    and Thinker Context 控制（慢于 Speaker，结果供下轮使用）
        T->>M: 读取用户记忆 + skill 轨迹
        M-->>T: 历史模式
        T->>T: Minimax m2.7
情绪分析 → Context 决策
(skill 是 context 的一部分)
        T->>T: 预测 next_likely_contexts
    end

    Note over S,T: Speaker 已完成回复，Thinker 仍在运行

    T->>D: cross-turn Context 注入
(情绪 + skill + guidance)
    Note right of D: 下一轮 Speaker 读取

    T->>D: 预组装 next context
→ prewarmed_contexts
    Note right of D: 下一轮若命中则直接使用

    T->>T: 审查 Speaker 本轮输出
    alt 发现灰色地带问题
        T->>D: 注入修正指导
→ 下轮 Speaker 读取
    end
核心时序：Speaker 和 Thinker 同时启动，但 Speaker 永远先完成（Doubao Lite 快，Minimax m2.7 + 记忆 API 慢）。Speaker 用的是上一轮 Thinker 写入的注入 + 预热 context。Thinker 本轮结果全部是 cross-turn：写入 deps → 下一轮 Speaker 读取。

打断处理：LiveKit 默认行为

AI 说话时用户出声 → 停止 Speaker → 等用户说完 → 重新触发 Speaker + Thinker。不区分附和/打断/补充，统一停止。
sequenceDiagram
    autonumber
    participant U as 🎤 用户
    participant LK as ⚙️ LiveKit
    participant S as 🗣️ Speaker
    participant T as 🧠 Thinker
    participant D as 📋 Deps

    Note over S,LK: Speaker 正在回复中...

    U->>LK: 用户出声
    LK->>LK: VAD 检测到用户语音
    LK--xS: 停止 Speaker

    Note over LK: 等待用户说完

    U->>LK: 用户继续说话...
    LK->>LK: ASR 输出文本

    Note over U,LK: 用户停止说话
VAD 检测到静音

    LK->>S: 重新触发 Speaker（新 ASR 文本）
    LK->>T: 重新触发 Thinker（新 ASR 文本）

    par Speaker 回复
        S->>D: 读取 context
        S->>S: 生成新回复
        S->>LK: TTS 输出
        LK-->>U: 🔊 语音输出
    and Thinker Context 控制
        T->>T: 情绪分析 → Context 决策
        T->>D: cross-turn Context 注入
    end
未来升级（需 GPU + 训练数据）：引入 DuplexCascade 式语义打断判断，区分"嗯"（附和，Speaker 继续）vs 真打断（停止 Speaker）vs 补充（拼入当前轮）。当前用 LiveKit 默认行为：统一停止 Speaker。

轮次生命周期

整个系统只有 4 个状态，全部由 VAD 驱动，无 LLM 参与触发判断。
stateDiagram-v2
    [*] --> Idle: 系统启动

    state "🎧 Idle
等待用户" as Idle
    state "🗣️ UserSpeaking
用户说话中" as UserSpeaking
    state "⚡ Processing
Speaker + Thinker 并行" as Processing
    state "🔊 AIResponding
Speaker 回复中" as AIResp

    Idle --> UserSpeaking: VAD: 检测到语音
    UserSpeaking --> UserSpeaking: 用户继续说
    UserSpeaking --> Processing: VAD: 静音（用户说完）

    Processing --> AIResp: Speaker 开始 TTS 输出

    AIResp --> Idle: Speaker 回复完毕
    AIResp --> UserSpeaking: VAD: 用户出声 → 停止 Speaker
极简状态机：4 个状态，全部由 LiveKit VAD 事件驱动。无 LLM 分类、无计时器、无状态判断逻辑。Speaker 和 Thinker 的并行在 Processing 状态内发生。

Thinker 预热机制：跨轮 Context 预组装

Thinker 核心职责是控制 Context（skill 是 context 的一部分）。每轮结束后预测下一轮可能的 context，提前组装好。下一轮命中则 Speaker 直接使用。

    participant S as 🗣️ Speaker

    Note over T,S: ── 第 N 轮 ──

    T->>T: 情绪分析 → Context 决策
当前 context: listen(悲伤)
    T->>M: 查询用户历史 context 轨迹
    M-->>T: listen→listen→untangle→decision

    T->>T: 预测 next_likely_contexts
= ["untangle(困惑)", "calm-body(焦虑)"]

    par 预组装
        T->>D: prewarmed["untangle"] = prompt + 记忆 + 情绪
        T->>D: prewarmed["calm-body"] = prompt + 记忆 + 情绪
    end

    Note over T,S: ── 第 N+1 轮 ──

    T->>T: Context 决策 → untangle(困惑)

    alt ✅ 命中
        S->>D: 读取 prewarmed["untangle"]
        D-->>S: 直接使用
    end

    T->>D: 更新 prewarmed（新预测）

    Note over T,S: ── 第 N+2 轮 ──

    T->>T: skill: relationship

    alt ❌ 未命中
        S->>S: 实时组装 context（正常流程）
    end

方案分层：现在实现 vs 未来升级

能力现在未来（需 GPU + 训练数据）
触发机制 现在 VAD 静音检测（LiveKit 默认） 未来 LTS 语义完整度分类器（DistilBERT 5ms）
打断处理 现在 用户出声 → 统一停止 Speaker（LiveKit 默认） 未来 DuplexCascade 语义区分：附和 / 打断 / 补充
全双工 现在 半双工 + 打断即停 未来 DuplexCascade 0.6s 微轮次 + LoRA 微调
状态判断 现在 无（VAD 二值：说话/静音） 未来 6 种状态（finished/thinking/crying/backchannel/interrupt/supplement）
Speaker/Thinker 并行 现在 同进程 Typed Protocol + 共享 deps —
Context 预热 现在 Thinker 预测 next_likely_contexts + 预组装 —
安全过滤 现在 prompt 约束 + 关键词 + Thinker 异步审查 —
记忆 现在 外部记忆模块 API 调用 —
RAG 暂不实现 未来 与记忆模块结合
