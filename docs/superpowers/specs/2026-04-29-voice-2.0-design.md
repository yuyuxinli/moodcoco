# Voice 2.0 — 1 + 2 Agentic Loop（基于复用 Pydantic AI 现有 agent）

**Date**: 2026-04-29
**Status**: DRAFT v2 — pending user review
**Predecessor**: r5 single-turn fast/slow on hand-rolled loop (`docs/voice-evolve-r5-handoff.md`)
**Big Idea**: 项目已有完整 pydantic-ai fast/slow agent（文字 chat 用），voice 2.0 不重写、只**桥接**到 LiveKit voice 链路。

## 0. 架构精神

- **1**：Pre-LLM 语音垫话（doubao-lite，现有不变）
- **2**：两条**完全独立的 pydantic-ai agentic loop**
  - **Fast** = `backend/fast.py:fast_agent`（minimax-m2.7 no-thinking）— 主线，唯一对用户出声
  - **Slow** = `backend/slow.py:slow_agent`（minimax-m2.7 thinking）— 后台支援，单向 mutate Fast 的 context

完成度本质：**voice 2.0 ≈ 把现有文字 chat 的 fast/slow agent 接到 LiveKit voice 链路，不是从零造**。

## 1. 框架选型（最重要的章节）

| 层 | 框架 | 责任 | 新写还是复用 |
|----|------|------|-------------|
| RTC / 音频 | **LiveKit Agents 1.5** | voice room、STT plugin、TTS plugin、VAD、RoomIO、浏览器接入、Pre-LLM 垫话 | r5 已写好，**复用** |
| Agent loop | **Pydantic AI 1.87** | Fast/Slow agentic loop（含多步 iter + tool_call schema + message_history + typed deps） | 文字 chat 已写好，**复用** |

```python
@fast_agent.tool
async def ai_voice_say(ctx: RunContext[FastThinkDeps], text: str) -> str:
    """Say a short Chinese sentence aloud. Use this in voice mode."""
    if ctx.deps.voice_session is None:
        return "skipped: not in voice mode"
```

## 3. 通信 — Slow 单向 mutate Fast.context

```
Slow.deps.fast_deps  (FastThinkDeps reference)
       ↓ tool_call: slow_inject_to_fast / slow_set_fast_retrieval / slow_attach_skill_to_fast
Fast.deps.dynamic_inject / .retrieval_block / .skill_bundle
       ↓ Fast 下一 iter compile_messages() 时读到
Fast.run() with these in system prompt
       ↓ ai_voice_say tool_call → session.say()
TTS → user
```

`FastThinkDeps` 扩展 4 个字段（voice 模式专属）：

```python
@dataclass
class FastThinkDeps:
    # ... 现有字段保留
    voice_session: AgentSession | None = None       # voice 模式注入，文字模式 None
    skill_bundle: list[str] = field(default_factory=list)
    retrieval_block: str = ""
    dynamic_inject: list[str] = field(default_factory=list)

    def voice_system_extras(self) -> str:
        """Voice 专用 system 增强，Fast LLM 调用前 compile 进 system prompt。"""
        parts = []
        if self.skill_bundle:
            parts.append("## Available skills\n" + "\n---\n".join(self.skill_bundle))
        if self.retrieval_block:
            parts.append("## Retrieved context\n" + self.retrieval_block)
        if self.dynamic_inject:
            parts.append("## Slow agent notes\n" + "\n".join(self.dynamic_inject))
        return "\n\n".join(parts)
```

Fast agent 的 `@fast_agent.instructions` 现有 hook 加一行 `voice_system_extras()` 即可。

## 4. 控制流 — 桥接层 ~30 行

```python
# backend/voice/entrypoint.py — 新 on_user_turn_completed

async def on_user_turn_completed(self, turn_ctx, new_message):
    user_msg = new_message.text_content or ""
    if not user_msg.strip():
        return

    session_id = self._room_name
    turn_id = uuid.uuid4().hex[:8]

    # 1. 准备 Fast deps（带 voice_session 引用）
    fast_deps = FastThinkDeps(
        session_id=session_id,
        voice_session=self.session,
        # ... 其他现有字段
    )

    # 2. 准备 Slow deps（带 fast_deps 引用 + Slow.context 跨 turn 状态）
    slow_deps = SlowThinkDeps(
        session_id=session_id,
        fast_deps=fast_deps,  # 让 slow tool 能 mutate fast_deps
        # ... 其他现有字段
    )

    # 3. 并行启动两条 pydantic-ai loop
    fast_task = asyncio.create_task(
        fast_agent.run(
            user_msg,
            deps=fast_deps,
            message_history=self._fast_history,  # 文字 chat 已有的 history 复用
        )
    )
    slow_task = asyncio.create_task(
        slow_agent.run(
            user_msg,
            deps=slow_deps,
            message_history=self._slow_history,  # Slow 跨 turn 保留
        )
    )

    # 4. Fast 是主线，必须等
    fast_result = await fast_task
    self._fast_history = fast_result.all_messages()

    # 5. Slow 不必等 — 它可以继续跑或被下一 turn 接续
    #    但要把 slow 的 message_history 收尾到 self._slow_history（用 done callback）
    slow_task.add_done_callback(self._collect_slow_history)
```

`pydantic-ai` 内置：
- multi-step iteration（默认 limit=10，调成 3）
- tool_call schema 自动生成
- stop 条件：LLM 返回纯文本（不再调 tool）
- message_history 跨 turn 保留

我们**不写 loop / 不管 stop / 不管 schema**——pydantic-ai 全做了。

## 5. Stop 条件（自然落到 pydantic-ai 内）

| Loop | Pydantic AI 自然 stop | 我们要不要额外干预 |
|------|----------------------|------|
| Fast | LLM 不再调 tool（输出空 text）→ run() 结束 | 加 `result_retries=3` 限制 max iter |
| Slow | LLM 不再调 tool / 显式调 `slow_pass` → run() 结束 | 加自定义检查：本 iter 没 mutate fast_deps → 强制 stop（pydantic-ai 暂没原生 hook，可包一层 mutation guard） |

补充 1 个 helper：

```python
    # Pydantic AI 0.5+ 有 retries hook，可以在 result hook 里检查
    ...
```

## 7. 路径分支（继承 r5）

| 路径 | 触发 | 用户感知 |
|------|------|----------|
| 短 | Fast 第一 tool_call 是 `ai_voice_say("嗯")` 然后没下一个 tool | ~1s 总 |
| 标准 | Fast iter 1 say + iter 2 stop（LLM 决定不再 say）；Slow 同步注入 1-2 个 skill | ~5s |
| 长 | Fast iter 1+2+3 都 say（multi-sentence reply）；Slow 注入 retrieval + skill | ~10s |

DP-continue 在 r5 是 hardcoded，2.0 不需要——Fast 自己决定要不要再 say。

## 8. Open Questions（精简到 5 个）

### 8.1 ai_voice_say vs ai_message：合并还是分开？
- A) 加一个 `ai_voice_say` tool（voice 模式，调 session.say()）；保留 `ai_message`（文字模式，写 chat history）
- B) 让 `ai_message` 在 `voice_session != None` 时自动走 voice，否则文字
- 倾向 **B**（少一个 tool，统一 LLM mental model）

### 8.2 Slow 跨 turn 状态在哪？
- A) `self._slow_state` per AgentSession 实例（room 死了就丢）
- B) 写 memU（持久 + 跨 session）
- 倾向 **A 起步**，memU 作 phase 2

### 8.3 fast_history / slow_history 跟 LiveKit ChatContext 怎么对齐？
- LiveKit ChatContext 是 voice 框架自己的对话历史
- pydantic-ai message_history 是它自己的
- 假设：每 turn 完成时 sync — `fast_history` 写回 `turn_ctx`，让 LiveKit 的 default reply suppression 能看到（保 chat_ctx 写回机制）

### 8.4 Fast 没调 ai_voice_say 怎么办？
- LLM 可能直接返回文本不调 tool（pydantic-ai 默认 result_type=str 时）
- voice 模式下要把 `result_type` 改成"必须调 tool"才有声音
- pydantic-ai 提供 `result_tool_name` / `result_validators` 解决；细节定 implementation 时确认

### 8.5 Slow mutation 检查机制
- pydantic-ai 没原生"iter 间检查 deps 是否 mutate"hook
- 实现选项：A) 自己包 `slow_agent.run()` 拦截每个 tool 调用前后 snapshot；B) Slow tool 内部记一个 mutation counter，下一 iter system prompt 提醒 LLM "你上 iter 没改 context，要么 stop 要么真做事"
- 倾向 **B**（更自然，让 LLM 自己 stop，不破坏 pydantic-ai 抽象）

## 9. 跟 r5 的对比

| 维度 | r5 | 2.0 |
|------|----|----|
| Fast 决策 | 单次 fast filler，hardcoded | pydantic-ai agentic loop 自主 say/stop |
| Slow 决策 | 单次 slow_v1 + DP-continue + slow_v2，hardcoded | pydantic-ai agentic loop，每 iter 1 个 skill tool_call |
| 通信 | Fast 输出后 chat_ctx 写回，slow 看 chat_ctx | Slow 单向 mutate fast_deps（typed reference）|
| 工具 | hardcoded merged_decision / continue_decider / skill_router | `@fast_agent.tool` / `@slow_agent.tool` 装饰器 |
| 状态 | 每 turn 从零 | pydantic-ai message_history + self._slow_state 跨 turn 保留 |
| 代码量 | 1100 行 fast_slow_agent.py | ~250 行 entrypoint 桥接 + ~150 行 tool 扩展 + 旧 1100 行**删掉** |
| Tool schema | 没有 | OpenAI tools schema（pydantic-ai 自动生成）|

**净增代码**：~400 行新 + 删除 1100 行 = **净减 700 行**。

## 12. 不在范围 / 暂不做

- 多角色 voice agent
- barge-in（用户打断）
- voice clone
- 多语言

## 13. 风险

| 风险 | 缓解 |
|------|------|
| pydantic-ai message_history 跟 LiveKit chat_ctx 写回不同步 | 每 turn 把 fast_history 末位 (assistant) write_to chat_ctx，保 LiveKit suppression 行为 |
| 文字 chat 现有 7 tool 在 voice 下可能不合适（如 ai_options 弹 UI） | 在 voice 模式 instructions 里明确"voice 模式不要调 ai_options/ai_mood_select 等 UI tool" |
| pydantic-ai max_iter 超限怎么办 | 设 `result_retries=3`，超限默认 fallback 到 r5 那句"嗯，我在这儿听着，慢慢说。" |
| Slow tool 失败 | pydantic-ai 默认 try/except，错误 → LLM 收到 error message 自己决定下一步 |
| minimax-m2.7 thinking mode 在 streaming 下偶发空流（r4 实测 27%） | r5 STAGE_K retry/fallback 保留作 safety net；2.0 由 pydantic-ai loop 内部 retry 替代 |
