术语速查

ASR Partial（部分识别）
流式语音识别的中间结果。用户还没说完，ASR 每 200ms 吐出一段已识别文本。LTS 的核心输入。
Dynamic Semantic Trigger
基于 DistilBERT 的二分类器，对每个 ASR partial 判断"语义是否已完整到可以开始推理"。推理仅需 ~5ms。
置信度阈值 τ
触发器的门控阈值，论文取 τ = 0.65。低于此值不触发 Thinker，避免在语义不完整时浪费推理。
Thinker（后台思考者）
后台模块。被触发后执行：输入纠错 → 语义分析 → 生成状态快照（JSON：corrected_text + key_variables + plan）。
Speaker（前台说话者）
前台模块。按"复述验证 → 查阅计划 → 求解回答"流程生成最终回复。参考 Thinker 注入的状态。
State Injection（状态注入）
Thinker 的输出（plan + key_variables）被注入 Speaker 的上下文，作为先验知识指导回复生成。
Thought Rollback（思维回滚）
用户继续说话导致语义偏移时，终止当前 Speaker，但保留 Thinker 已积累的有效状态，合并到下轮上下文。
TTFS（首句时间）
Time To First Sentence，从用户说完到系统说出第一句话的端到端延迟。LTS 核心优化指标。

核心思想

不是每个 ASR 片段都值得送给 LLM 推理。
Dynamic Semantic Trigger 在 ASR partials 上计算语义完整度，只在置信度超过 τ=0.65 时才触发 Thinker——减少无用推理、降低延迟。 Thinker 在后台生成推理计划（JSON 状态快照），Speaker 在前台根据计划快速生成回复。二者异步并行，Listen/Think/Speak 三阶段时间重叠。
类比：同声传译员不是每听到一个词就翻译，而是等到听到一个完整的意思单元后才开口。 LTS 的触发器就是这个"意思单元够了"的判断器。

触发器训练

  • 基座：DistilBERT（轻量，~5ms 推理）
  • 数据：GPT-4o 在 GSM8K+MMLU-Pro 文本中标注语义边界 [T] token
  • 模拟 ASR 流式切片，生成 ~10 万条累积前缀样本
  • 学习率 5e-5，二分类交叉熵

双重过滤机制

  • 阈值门控：confidence > τ=0.65 才触发
  • 去重抑制：当前文本 = 上次触发文本 → 跳过（防抖动）
  • 太低 → 碎片触发过多，浪费推理
  • 太高 → 触发过晚，延迟增加

Thinker / Speaker 双角色协作

与 PredGen 的关键区别：PredGen（投机生成）在用户改口时需要丢弃全部预测并重新生成，打断率高达 95-99%。 LTS 的 Thought Rollback 保留有效推理状态，打断率仅 5-10%。

实验结果

主力骨干 Qwen3-8B，评估 4 个 benchmark：VERA（数学/科学推理）、Spoken-MQA（多步数学问答）、BigBenchAudio（开放域）、Pause-and-Repair（自纠正/改口）。

方法 BigBench Acc% BigBench TTFS MQA Acc% MQA TTFS 打断率
Serial (Think) 73.8% ~84,000ms 84.0% ~43,000ms —
PredGen (Think) 71.6% ~46,000ms 83.5% ~25,000ms 95-99%
LTS-VAD (Think) 71.5% ~45,000ms 83.5% ~26,000ms 70-90%
LTS-VoiceAgent 71.9% 338ms 78.5% 332ms 5-10%
Qwen2.5-Omni (E2E) 43.1% 333ms 59.9% 635ms —
核心结论：LTS-VoiceAgent 在 BigBench 上达到 71.9% 准确率（接近 Serial Think 的 73.8%），但 TTFS 从 84 秒降到 338ms——延迟降低约 250 倍，同时打断率仅 5-10%。 端到端模型（Qwen2.5-Omni）延迟虽低但准确率仅 43.1%。
消融实验： 去掉 Semantic Trigger → 准确率降 3%，无效推理次数增 3.4×，打断率增 7.3×。 去掉 Orchestrator → 准确率降 6%，打断率增 1.8×。两个组件缺一不可。

对 moodcoco 的启发

✓ 可以借鉴的

  • Semantic Trigger 替代"每条消息都触发 Slow"——在 ASR partials 上计算语义完整度，只在用户意图清晰时才启动 Slow Agent，节省计算
  • Thinker/Speaker 分离验证了 Fast/Slow 拆分——LTS 的实验证明：Thinker 做重推理、Speaker 做轻生成，这种分离比"一个 LLM 同时思考和回答"更高效
  • Thought Rollback 机制——moodcoco 的 Slow 结果 carryover 已经是类似思路，但 LTS 更精细：保留有效状态、只回滚无效部分
  • State Injection = slow_inject_to_fast——LTS 的 JSON 状态注入映射到 moodcoco 的 slow_inject_to_fast / slow_set_fast_retrieval

⚠ 需要注意的

  • 触发器需要按领域训练——LTS 的训练数据来自数学/科学，情绪对话的语义完整性信号完全不同（犹豫、重复、欲言又止 ≠ 语义不完整）
  • 论文没有多轮对话评估——所有 benchmark 都是单轮问答，情绪陪伴是多轮连续对话，触发器行为可能不同
  • Thinker 输出是结构化 JSON——moodcoco 的 Slow 输出目前是非结构化的策略/Skill 选择，迁移需要设计 JSON schema
  • 单 A100 推理——Qwen3-8B 的推理成本在生产部署中需要考量
最值得复现的工程思路：
STT partial stream → 语义触发器（判断是否值得启动后台推理） → 后台 Thinker 生成 state/plan/facts → 前台 Speaker 在 EOT 或足够确定时开始说 → TTS 只接 Speaker 的可说文本。

这比"等 STT final 后再问一个大 LLM"更像真正的语音 Agent。 对 moodcoco 而言，第一步可以先实现一个简化版 trigger：用 LLM 自身判断 ASR partial 是否"意图明确"，不需要训练 DistilBERT——先验证"选择性触发 Slow"这个策略是否对情绪场景有效。
