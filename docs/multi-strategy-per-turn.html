Modeling Multiple Support Strategies
within a Single Turn

for Emotional Support Conversations
Zhu, Dou, Li, Guo, Chen, Su, Zhang, Kong Soochow + Alibaba + Xiamen arXiv 2604.17972 2026-04

30 秒版本

现有 ESC 研究假设每轮回复只用一种策略，但真实数据中 17.7% 的 supporter 回复包含 2+ 种策略。本文首次将 ESC 重构为多策略话语生成任务，提出 All-in-One（一次解码全部策略-回复对）和 One-by-One（迭代生成直到停止）两种范式，并用认知推理链 + GRPO 强化学习优化策略选择。结果：One-by-One + Reasoning + RL 在对话级 Success Rate 达 40%（单策略基线仅 13.85%），人类评估全维度领先。

ESConv 真实案例：一条 supporter 回复中自然融合了自我披露、肯定和提问三种策略

两种生成范式

All-in-One

一次解码全部

对话上下文
-->
[认知推理]
-->
单次解码
-->
S1+R1, S2+R2, S3+R3

输出格式：策略紧跟回复，所有 (策略, 回复) 对拼接为一个序列，单次自回归解码完成。

utsys = concat(st,1, rt,1, ... , st,N, rt,N)
+ 计算效率高（一次前向）
+ 策略间可并行建模关联
- 联合预测多策略增加噪声
- EMR 比单策略基线略降（23.61 vs 25.21）
One-by-One

迭代生成

对话上下文
-->
[认知推理]
-->
S1+R1 + flag
-->
S2+R2 + flag
-->
... (until STOP / K=3)

每步生成一个 (策略, 回复, 停止标志)，停止标志指示是否继续生成下一对，最多 K=3 步。

yt,i = concat(st,i, rt,i, ft,i)   f=0 继续 / f=1 停止
+ 每步独立推理，策略更精准
+ EMR 与单策略基线持平（24.99 vs 25.21）
+ 最终效果全面最优
- 需多次前向，延迟更高
- 需要额外训练停止判断

认知推理 + 强化学习机制

四节点认知推理链

在生成回复前，模型先进行结构化认知推理（<think> ... </think>），由四个节点组成：

Context
外部情境
学业压力、人际冲突等
-->
Cognition
认知评估
用户的信念、自我判断
-->
Emotion
情绪状态
焦虑、悲伤、挫败
-->
Support Plan
策略规划
共情+重构+建议

推理链从 4 个大模型（DeepSeek-R1, Qwen3-235B, GPT-5, Gemini-2.5-Flash）蒸馏而来，取互补优势。实验证明混合 4 个教师模型的推理链效果最好——GPT-5 擅长 BLEU-4，Gemini 擅长 ROUGE-L，DeepSeek-R1 擅长 BERTScore 和 EMR。

GRPO 强化学习优化

在 SFT 之上用 Group Relative Policy Optimization (GRPO) 进一步优化，以任务特定奖励函数引导策略选择和回复质量。

All-in-One 奖励
r1(y) = LR(sy, sr)  if rfmt(y)=1,  else 0

LR = Levenshtein Ratio，衡量预测策略序列与参考策略序列的编辑距离相似度。r_fmt 检查输出格式是否合规。

One-by-One 奖励（额外奖励停止判断）
r2(y) = LR(sy, sr) + rflag(y)  if rfmt(y)=1,  else 0

r_flag = 1 当停止标志预测正确时，鼓励模型学会"何时该停，何时该继续生成下一个策略"。同时下采样单策略实例以平衡奖励分布。

对 moodcoco 的价值

多策略组合建模范式

moodcoco 的 coco 经常需要在一条回复中同时"共情+引导+重构"。本文给出了两种可落地的范式——All-in-One 适合低延迟场景（语音 fast path），One-by-One 适合需要精细推理的场景（slow path）。

认知推理链可直接复用

Context -> Cognition -> Emotion -> Support Plan 四节点链与 moodcoco 的"看见情绪-看见原因-看见模式-看见方法"评估维度天然对齐，可作为 prompt 设计的结构模板。

RL 优化策略组合

用 GRPO + Levenshtein Ratio 奖励优化策略序列，比单纯 SFT 的策略准确率提升 34%（EMR 25.21 -> 33.53）。moodcoco 可以用类似方法对 coco 的策略选择做 offline RL。

"何时停"的建模

One-by-One 的 stop flag 机制解决了"该用几种策略"的问题，避免过度堆砌。对 moodcoco 的语音场景尤其关键：回复太长用户会失去耐心，太短又显得缺乏支持。

局限性

  • 1 多策略生成比例仍低于人类。模型生成的多策略话语占比最高仅 8.4%（All-in-One+Rea.+RL），远低于 ESConv 参考数据的 18.9%。训练数据中单策略实例占 82.3%，模型倾向于保守。
  • 2 对话级评估依赖模拟 seeker。用 GPT-5 模拟 seeker 并评估情绪缓解程度，无法完全捕捉真人情绪交互的细微差别。
  • 3 仅在 ESConv 上验证。ESConv 是英文、众包标注的数据集，未在其他情感支持语料（如中文场景）或真实部署环境中验证泛化性。
  • 4 策略集固定为 8 种。ESConv 定义的 8 种策略可能无法覆盖所有支持行为（如幽默、沉默、非语言回应），在语音场景中策略空间需要扩展。
  • 5 延迟问题未讨论。One-by-One 需要多次前向推理，在实时对话（尤其语音）中的延迟代价未被量化。
