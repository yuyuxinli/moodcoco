核心架构: Dual-Loop Framework

TheraMind 将咨询师的认知过程拆为两个层级的循环: Intra-Session Loop 管每一轮对话的战术决策，Cross-Session Loop 管跨 session 的战略规划。这是论文的核心贡献。

Intra-Session Loop
轮内战术 -- 每轮对话执行一次
1. Reaction Classifier 情绪感知
从用户话语中解析出结构化状态三元组
St = (Et, It, At)
Et=主情绪 | It=[0,1] 情绪强度 | At=Cooperative/Resistant
↓
2. Memory Recall 记忆检索
从跨 session 历史中检索相关记忆摘要，无相关则返回 null
Mt = Φmemory(Ut, H)
↓
3. Response Strategy Selector 策略选择
根据情绪状态，从 12 种策略中选择一个，输出策略名 + 30 字指导
σt = f_strategy(St)
↓
4. Therapeutic Phase Analyzer 阶段分析
判断当前处于哪个咨询阶段（投入/探索/整合）
Pt = f_phase(Tk, Ht-1)
↓
5. Response Generator 回复生成
综合所有信号生成最终回复
Rt ~ G(- | Ut, Ht-1, Tk, σt, Pt, Mt)
Cross-Session Loop
跨 session 战略 -- 每次 session 结束执行
1. Session 结束
收集完整对话历史 Hk
↓
2. Therapy Evaluator 疗效评估
对本 session 使用的疗法打分，评估是否产生治疗效果
Ek = f_eval(Hk, Tk)
↓
3. Therapy Selector 疗法选择
根据评分 + 对话历史，决定维持当前疗法或切换
Tk+1 = f_select(Tk, Hk, Ek)
↓
4. 下一 Session 启动
带着新疗法 Tk+1 进入 Intra-Session Loop
核心逻辑
有效 → 维持当前疗法
无效但用户配合 → 换技术手段
无效且用户抵触 → 换整个疗法框架
Intra-Session  ←→  Cross-Session  |  通过 Memory + Therapy Config 连接

Strategy Selection 机制详解 (论文核心)

这是 TheraMind 最值得深入的部分。论文将 "咨询师下一步该怎么回" 这个模糊问题，分解为了一个可计算的决策流程。

12 种 Response Strategy 完整列表

论文将 12 种策略按用户态度分为两组。反直觉设计: 用户越配合，越用 challenging 策略推动改变；用户越抵触，越用 supportive 策略修复关系。这与真实咨询师的判断逻辑一致。

策略名 类型 触发条件 作用
Interpretation Challenging Cooperative 对用户的行为/情绪做深层解读
Confrontation Challenging Cooperative 指出矛盾或不一致之处
Invite to Take New Perspectives Challenging Cooperative 邀请从新角度审视问题
Invite to Explore New Actions Challenging Cooperative 邀请尝试新的应对方式
Restatement Supportive Resistant 用自己的话重述用户的内容
Reflection of Feelings Supportive Resistant 映射并确认用户的情绪状态
Self-disclosure Supportive Resistant 咨询师分享自身经验以建立连接
Inquiring Subjective Info Supportive Resistant 询问感受、想法等主观体验
Inquiring Objective Info Supportive Resistant 询问事实性信息
Affirmation & Reassurance Supportive Resistant 肯定用户的感受或努力
Minimal Encouragement Supportive Resistant 用简短回应鼓励继续表达
Answer Supportive Resistant 直接回答用户的问题
Strategy Selector 的输出格式
输出: 策略名 + 最多 30 字的 guidance text（具体指导这一轮该怎么用这个策略）
这个 guidance 和策略名一起作为 prompt 注入 Response Generator。

Challenging vs Supportive: 判断逻辑

这是论文中最有临床智慧的设计决策。

核心原则

用户态度 At 是唯一的一级分流信号:

  • Cooperative (配合) → 用户当前有能量和意愿 → 适合 Challenging 推动改变
  • Resistant (抵触) → 用户处于防御状态 → 需要 Supportive 重建安全感

为什么是"反直觉"的?

多数产品的直觉是: 用户难受 → 安慰，用户好了 → 少管。TheraMind 的设计刚好相反:

  • 用户配合时不是放松，而是抓住窗口期做有深度的干预（Interpretation, Confrontation）
  • 用户抵触时不是继续推进，而是退回基础操作修复关系（Reflection, Restatement）

这和 Motivational Interviewing 的 "roll with resistance" 原则完全一致，也和 Hill's Helping Skills Model 的 challenge/support 平衡对应。

二级信号: 情绪 + 强度

在确定 Challenging/Supportive 大方向后，情绪类型 Et 和强度 It 影响具体选哪个策略:

  • 高强度 Fear + Cooperative → 可能选 "Invite to Take New Perspectives"（不适合 Confrontation）
  • 低强度 Sadness + Resistant → 可能选 "Minimal Encouragement"（不需要完整的 Reflection）

Resistance Detection

论文还有一个独立的 Resistance Detection 布尔判断，检测用户是否在当前轮出现了偏离治疗方向的行为（例如转移话题、否认问题、攻击咨询师）。这与 Cooperative/Resistant 态度标签形成双层检测。

Therapy Selection: 跨 Session 疗法切换

这是 Cross-Session Loop 的核心，解决的是 "什么时候该换疗法" 的问题。

工作流程

  1. Initial Selection: 首次 session 前，根据用户 intake profile（主诉、基本信息）用 LLM 选择初始疗法
  2. Session 执行: 用 Intra-Session Loop 完成 6 轮以上对话
  3. Post-Session Evaluation: Therapy Evaluator 对整个 session 打分，评估维度:
    • 治疗效果（用户情绪是否有改善?）
    • 用户参与度（是否主动配合技术?）
    • 技术整合度（疗法的具体技术是否被有效使用?）
  4. Decision: Therapy Selector 解读评分 + 对话历史，做出三种决策之一:
    • 维持当前疗法
    • 微调技术细节（同一疗法框架内换技术）
    • 完全切换到新疗法

论文举例

"如果评估结果显示用户对 CBT 的参与度不足，尽管疗效中等，Therapy Selector 可能推理认为转向以来访者为中心的方法（Client-Centered Approach）更合适" -- 因为参与度低意味着当前疗法的结构化要求超出了用户的承受能力。

支持的疗法模态

论文未给出封闭列表，由 LLM 自主选择。已明确提到的包括:

  • Cognitive Behavioral Therapy (CBT)
  • Client-Centered Therapy
  • Motivational Interviewing
  • 其他（由 LLM 根据专业知识决定）

评估指标与结果

数据集

CPsyCounR: 3,134 份匿名中文心理咨询报告，采样 100 个 case（10 个心理问题类别 × 10），每个 case 模拟 6 轮 session 对话。

类别: 恋爱 / 家庭 / 情绪 / 青少年 / 社交 / 压力 / 成瘾 / 焦虑 / 自我成长 / 罕见

评估维度 (4-point scale, 0-3)

Single-Session 指标
  • T.Alliance: 治疗联盟（目标/任务/关系）
  • Interaction: 临床深度 + 认知挑战
Multi-Session 指标
  • Coherence: 引用和延续历史对话
  • Flexibility: 策略是否有调整
  • Empathy: 情绪发展追踪
  • T.Attunement: 干预与阶段匹配度

对 moodcoco 的价值

1. Response Strategy 机制可直接借鉴

TheraMind 的 12 策略分类 + Cooperative/Resistant 二分法，可以直接迁移到 moodcoco 的 voice agent response 生成环节。具体做法:

  • 在 fast path 做 Reaction Classification（情绪 + 态度），延迟 < 200ms
  • 态度判断结果决定 strategy 大方向（Supportive/Challenging）
  • Strategy 名 + guidance 注入 slow path 的 response 生成 prompt

2. "态度" 比 "情绪" 更重要的洞察

TheraMind 把用户态度 (Cooperative/Resistant) 作为一级分流信号，而情绪类型是二级信号。这对 moodcoco 的启发: 不要只看用户说了什么情绪，更要看用户对"被帮助"这件事的态度。一个生气但愿意谈的人和一个生气且抗拒的人需要完全不同的 response。

3. Cross-Session 疗效评估可简化迁移

moodcoco 不需要完整的疗法切换（产品不做正式心理治疗），但"评估上一次对话的效果，调整下次策略"这个模式非常有价值。可以:

  • 每次 session 结束时 LLM 打一个简单的 effectiveness 分数
  • 下次 session 开始时根据分数调整 response 的深度和方向

4. Ablation 数据的启示

Memory 贡献最大 (75%)，Strategy Selection 是 68.4%。这说明跨 session 记忆是最高优先级，策略选择是第二优先级。moodcoco 应先做好 memory，再精细化 strategy。

5. 12 策略列表是可靠的参考

这 12 个策略不是作者发明的，而是基于 Hill's Helping Skills Model（临床心理学经典框架）。moodcoco 可以直接使用这个列表作为 response strategy 的分类体系，不需要从零设计。

局限性

方法论层面

  • 模拟测试: 全部评估基于 LLM 扮演患者，无真实用户验证
  • 单语种: 仅中文 CPsyCounR 数据集，跨语言泛化未知
  • 疗法选择无约束: LLM 自由选择疗法，缺乏临床合理性检验
  • Attitude 二分法过简: Cooperative/Resistant 的二值分类忽略了中间状态（矛盾、犹豫、被动配合等）

工程层面

  • 延迟: 每轮需串行调用 5 个 LLM 模块，推理延迟高
  • 成本: DeepSeek-V3 作为 backbone，每轮 5 次调用 × 6 session 对话成本可观
  • 无语音支持: 纯文本对话，未考虑语音场景的实时性约束
  • Memory 无上限管理: 论文未提及长期使用后记忆的压缩或淘汰策略
对 moodcoco 迁移的风险提示
• 5 模块串行不适合 voice agent 的实时场景，需要并行化或选择性跳过
• Attitude 判断在语音场景可以利用 prosody/tone 信号增强，但论文无此基础
• Strategy guidance 的 30 字限制在 voice 场景可能不够/太多，需要实测
