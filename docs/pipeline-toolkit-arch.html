术语速查

Cascade Pipeline
级联管线。VAD→STT→LLM→TTS 按阶段串行（可部分流式重叠），是当前语音 Agent 主流架构。
Modular Backend
可插拔后端。每个管线节点（STT/LLM/TTS）支持多种实现，运行时配置切换，不改代码。
Speculative Generation
投机生成。在不确定用户是否说完时就开始生成 LLM 回复，赌对了省延迟，赌错了丢弃重来。
EOT（End-of-Turn）
轮次结束检测。判断用户是否已经说完。传统用 VAD 静音检测，Iris 用置信度阈值做提前判断。
Abort-Retry
中止重试。投机生成被打断时丢弃已有结果，等新的 EOT 信号后重新生成。
Edge Deployment
边缘部署。将服务运行在靠近用户的边缘节点（如 Cloudflare Workers），减少网络延迟。
Durable Objects
Cloudflare 的有状态边缘计算。Iris 用它维护对话状态，使无状态 Worker 能管理多轮对话。

Part B: Iris Voice Agent

GitHub: cloudflare/iris  |  Cloudflare Workers + Durable Objects  |  亮点：Speculative EOT

架构本身是标准级联（Deepgram STT + Groq LLM + ElevenLabs TTS）， 但有一个值得注意的工程技巧：Speculative EOT Generation——在仅有 30% 置信度认为用户说完时就开始生成， 赌对了大幅降低延迟，赌错了 abort 重来。
Speculative EOT 投机生成流程
T0
🎤 用户正在说话… VAD 检测到语音活动，STT 流式转写中
T1
🎲 EOT 置信度 30% → 投机启动 不等 VAD 确认用户说完，提前将当前 transcript 送入 Groq LLM 开始生成回复
❌ 赌错了：用户继续说
VAD 检测到用户还在说话 →
ABORT 已生成的回复 →
丢弃全部投机结果 →
等下一个 EOT 信号重试
✓ 赌对了：用户确实说完了
VAD 确认静音 →
回复已部分生成完毕 →
立即送 TTS，用户更快听到 →
节省 LLM TTFT 的等待时间
本质是一个赌注：用多余的计算（abort 掉的无用生成）换取延迟降低。 如果用户长句占比高（abort 率高），投机生成反而浪费；如果用户多为短句且停顿清晰，收益显著。

对 moodcoco 的启发

来自 HF speech-to-speech

  • 模块化后端验证——moodcoco 的 STT/TTS 插件化（XfyunSTTPlugin, MiniMaxTTS）已经走在这个方向上
  • 本地对比工具——可以用这个框架快速测试：Parakeet vs Whisper vs FunASR × Kokoro vs Qwen3-TTS，找出中文场景最优组合

来自 Iris Voice Agent

  • Speculative EOT 可叠加到 VAD 上——当 VAD 置信度中等（不确定用户说完没）时，投机启动 Fast Agent，用户继续说就 abort
  • 边缘部署思路——如果 moodcoco 要做全球化，CF Workers 方案值得参考
Speculative EOT vs LTS Semantic Trigger：同一思路的两个层次
Iris 在 管线层 做投机（不确定用户说完时就开始生成回复）， LTS-VoiceAgent 在 推理层 做投机（不确定语义完整时就开始后台思考）。
两者可以叠加：在 ASR partial 阶段用语义触发启动 Thinker，在 EOT 不确定时投机启动 Speaker。 moodcoco 如果要做极致低延迟，这是两个可以分层实现的优化点。
